Oui, le plus efficace est de lui transmettre un document de passation complet, avec l’objectif final, l’état actuel, l’architecture, les contraintes de sécurité et les prochaines étapes. Voici un bloc prêt à copier-coller à l’autre IA.

Contexte de reprise du projet

Je développe progressivement une application Streamlit dans Amazon SageMaker AI Studio, connectée à Amazon Bedrock.

L’application doit devenir un assistant personnel polyvalent, utilisable sur plusieurs projets. Elle n’est pas destinée à un métier unique et ne repose pas actuellement sur un RAG.

À plus long terme, je souhaite faire évoluer cette application vers une architecture multi-agents, dans laquelle plusieurs modèles peuvent :

analyser une même demande ;
proposer des solutions différentes ;
se critiquer mutuellement ;
débattre ;
sélectionner ou synthétiser la meilleure réponse ;
utiliser des outils de manière contrôlée.

Je souhaite avancer progressivement, fichier par fichier, sans recevoir plusieurs étapes en même temps. Quand un fichier doit être modifié, je préfère recevoir le fichier complet prêt à copier-coller, plutôt que quelques fragments dispersés.

Cet outil ne doit jamais écrire directement dans le fichier cible.

générer un aperçu diff ;

Les fonctions suivantes sont réservées à Streamlit et ne doivent jamais être données au modèle :

Lorsqu’une proposition est approuvée :

vérifier que le fichier n’a pas changé depuis la proposition ;
créer une sauvegarde horodatée s’il existait ;
écrire dans un fichier temporaire ;
effectuer un remplacement atomique ;
afficher le résultat dans Streamlit.

Les sauvegardes sont placées dans :

/home/sagemaker-user/app_chat/backups


La suppression de fichiers reste interdite.

Sécurité attendue

Le modèle ne doit jamais pouvoir :

sortir du workspace ;
utiliser un chemin absolu ;
lire des secrets AWS ;
modifier le code de l’application sans workflow d’approbation ;
supprimer un fichier ;
exécuter une commande shell ;
appliquer lui-même une proposition ;
prétendre qu’un fichier a été modifié avant l’approbation ;
écraser une version plus récente qu’il n’a pas lue.

Les fonctions d’approbation doivent être appelées exclusivement par l’interface Streamlit après un clic de l’utilisateur.

Optimisation des coûts et tokens

Le budget est relativement confortable, mais l’application doit rester raisonnablement optimisée.

Principes à conserver :

Ne pas envoyer automatiquement tous les fichiers au modèle.
Lister les fichiers avant de les lire.
Rechercher un terme avant de lire plusieurs documents.
Lire les fichiers par extraits, par exemple 8 000 caractères.
Indiquer au modèle comment continuer à partir d’un offset.
Ne pas renvoyer tout le contenu après une écriture.
Utiliser Sonnet par défaut.
Réserver Opus 4.7 ou 4.8 aux demandes complexes.
Comptabiliser tous les appels au modèle lorsqu’un agent utilise plusieurs outils.
À terme, limiter ou résumer l’historique ancien.

Actuellement, toute la conversation visible est reconstruite puis envoyée à l’agent. Ce point devra être optimisé lorsque l’historique deviendra long.
